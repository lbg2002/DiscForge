# 候选三：wodim 锁页隔离

新日志中的 Cannot allocate memory / Cannot open SCSI driver 出现在通信层初始化；不是“没有安装 SCSI 驱动”的充分证据。

上游同类缺陷记录：https://bugzilla.redhat.com/show_bug.cgi?id=1583845#c12

MCL_CURRENT | MCL_FUTURE 可能在有限额度下先成功，后续分配因可锁内存额度不足失败。仅减小 FIFO 无法保证其他分配仍有足够额度。

本版使用 QProcess::setChildProcessModifier，仅在 wodim 子进程 exec 前将 RLIMIT_MEMLOCK 的软硬限制设为零，使其可选的锁页操作不能生效。不会升权，不改系统设置，也不会改变父程序或其他工具的资源限制。无法设置时中止启动，不尝试绕过。

测试：

- 脚本型模拟 wodim 实测子进程软硬额度均为零。
- 父进程和普通 shell 工具仍保留原额度。
- 独立 C/C++ 小程序在 8 MiB 额度下能成功锁页，但随后 16 MiB 映射失败；走相同 wodim 子进程入口时锁页未生效，后续 16 MiB 映射成功。
- 核心、界面、虚拟多区段测试通过，安装包解包界面自检通过。

当前代理环境无法访问光驱设备节点，不具备实际通信、物理刻录或 Windows 读取的验证结果。对旧 Python 与新程序在同环境下的硬件差异尚未完成对照。
