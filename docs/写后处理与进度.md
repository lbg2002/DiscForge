# 候选四：写后处理与进度

用户实盘日志显示：wodim 完成数据写入及 Fixating，随后立即调用 udisksctl 挂载时报告“not a mountable filesystem”。当前只能确认写入工具报告完成，不能推断文件系统及数据完整性已经验证。

修复前的顺序：写入 → 关闭区段 → 挂载并校验 → 弹出。挂载或校验抛异常会提前退出，跳过弹出。原界面只有日志，没有明确进度。

修复后：

1. 请求 UDisks2 Block.Rescan 刷新设备内容识别（仅刷新，不格式化，不提升权限）；请求若不可用记录诊断，继续有限等待。
2. 只对介质未就绪、尚无可挂载文件系统等状态重试挂载；最多16次，间隔2秒，每次命令有超时。权限错误直接失败；兼容桌面已经自动挂载的竞争。
3. 校验和弹出各自捕获错误。启用自动弹出时，校验异常后仍尝试弹出；最终警告分别说明“已写入、校验未完成、已弹出/弹出失败”。未完成写入时不自动执行这些后处理。
4. 阶段进度条始终位于窗口顶部，可显示映像生成、写入、校准、区段关闭、等待介质、文件校验、弹出及用时。只使用实际工具报告和字节读数，未知进度使用等待动画，不虚构总进度。
5. 校验使用分块 SHA-256，涵盖本次与旧有文件。内容不符时不能显示校验100%通过。

新增回归测试覆盖：真实示例输出、忽略FIFO填充率、回车和分块日志、挂载第3次才就绪、权限错误不重试、等待超时、自动挂载竞争、校验失败仍弹出、弹出失败保留校验结果、禁用校验、未写入不做后处理、校验百分比与内容错误。

硬件验证限制：本轮不能直接访问光驱。设备刷新与等待策略针对日志中的识别时序问题，但实际错误也可能涉及文件系统或介质，不能在用户复测前断言修复成功。
